# Guardian — модуль защиты детей

Модуль обнаружения и блокировки контента, связанного с вербовкой, грумингом и
сексуальной эксплуатацией несовершеннолетних, для Telegram-бота BASIC.FOOD.

## Что модуль делает

| Возможность | Где реализовано | Что реально происходит |
|---|---|---|
| **Обнаружение** | `scan_text()` | Взвешенные эвристики (укр/рус/англ) помечают признаки вербовки/груминга/торговли. Только текст. |
| **Блокировка** | `enforce_in_managed_chat()` | Удаляет сообщение и банит пользователя — **только в чатах, где бот является администратором**. |
| **Досье** | `record_evidence()` | Складывает **только метаданные** (ссылка, юзернейм, время, фрагмент текста, сигналы) в очередь на проверку. |
| **Передача в органы** | `build_authority_report()` | Готовит текст отчёта и ссылки на официальные приёмники. **Подаёт человек.** |

## Жёсткие границы (встроены в код, не обходятся)

1. **Модуль никогда не скачивает, не хранит и не пересылает сам материал.**
   `record_evidence()` имеет строгий allowlist полей (`_ALLOWED_EVIDENCE_FIELDS`)
   и отбрасывает всё, кроме метаданных. Хранение самого материала — преступление
   даже с благими намерениями; для работы с ним есть защищённые каналы органов.
2. **Никаких атак, DoS или массовых автожалоб.** Единственные рычаги —
   удаление/бан в своих чатах и передача доказательств. Бот **не может** и не
   пытается удалять чужие каналы: такой возможности нет ни у кого, кроме самого
   Telegram и правоохранителей.
3. **Человек в цикле.** Автоматика только помечает и складывает в очередь.
   Внешние отчёты в органы подаёт человек после проверки.

## Логика уровней риска

`scan_text()` суммирует веса сработавших сигналов:

- **high** (score ≥ 5) → в управляемом чате: удалить + забанить, и зафиксировать досье.
- **review** (score ≥ 3) → только зафиксировать в очередь на проверку человеком.
- **low / none** → без действия.

Одиночный сигнал вербовки/торговли даёт максимум `review` — автоблокировка
наступает только при однозначной комбинации или явных индикаторах CSAM-каналов.
Это сделано намеренно, чтобы не банить безобидные фразы (например, «корм для
детей питомцев» попадёт лишь в очередь на проверку, где человек его отклонит).

## Как это работает в боте

`orchestrator.py` прогоняет каждое входящее сообщение через Guardian **до**
передачи в поддержку (`_guardian_screen`). Если сообщение заблокировано как
высокорисковое — дальше по конвейеру оно не идёт.

## CLI

```bash
# Обзор очереди доказательств, ожидающих проверки человеком
python main.py guardian-queue

# Собрать пакет для ручной подачи в органы по конкретному случаю
python main.py guardian-report <report_id>
```

|---|---|---|
| `ncmec` | NCMEC CyberTipline (международный) | https://report.cybertip.org |

| `telegram_abuse` | Telegram Abuse | abuse@telegram.org |

## База данных

Миграция `supabase/migrations/003_child_safety_tables.sql`:

- `pablo_csam_reports` — очередь доказательств (только метаданные) со статусами
  `pending_review` → `confirmed` / `dismissed` / `submitted_to_authority`.
- `pablo_moderation_actions` — журнал действий модерации (удаление/бан).

Обе таблицы под RLS: полный доступ у service role, чтение/триаж — у админов.

## Требования к боту

Чтобы блокировка работала, бот должен быть **администратором** нужного чата с
правами «удалять сообщения» и «банить пользователей». В чатах, где бот не админ,
доступно только обнаружение и фиксация досье для передачи в органы.
