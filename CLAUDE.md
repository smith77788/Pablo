## Один проект, одна ветка

| | |
|---|---|
| **Проект** | **Infragram** — Telegram-инфраструктура и массовые операции |
| **Код** | `tg-manager/` — это весь продукт |
| **Рабочая ветка** | `claude/telegram-bot-services-xfAh6` — **единственная**, с неё идёт автодеплой на Railway |
| **Спутник** | `assistant/` — личный бот, едет в том же контейнере (`start-all.sh`), своё окружение |

`main` приведена к рабочей ветке 2026-09-04 и дальше остаётся **зеркалом**:
открывший репозиторий по умолчанию видит настоящий проект, но работа и деплой
идут в `claude/telegram-bot-services-xfAh6`. Пушить в `main` не нужно — её
обновляют вручную после того, как работа влита в рабочую ветку.

Другой ветки для работы нет. Не создавайте параллельных: репозиторий уже
пережил 21 ветку от разных агентов, из них половина — несвязанные истории, и в
них терялась готовая работа (модуль `wb_chat`, `budget_radar`, закрытая дыра
SSRF, весь свод правил проекта). Всё это возвращено 2026-09-04; точки
восстановления любой ветки — `docs/BRANCH_RESTORE_POINTS.md`.

Автодеплой означает: **пуш в рабочую ветку уезжает в прод**. Перед пушем —
полный прогон тестов, а не выборочный.

## Как проверять

```bash
cd tg-manager
python -m pytest tests/ -q        # ~4500 тестов, ~3 минуты
```

CI (`.github/workflows/tests.yml`) гоняет то же самое и только по `tg-manager/**`.
**Красный тест — стоп.** Ни один не отключается, не пропускается и не
переписывается «чтобы прошёл»: если он мешает, сначала поймите, что он защищает.

### Храповики — не трогать без причины

В наборе есть тесты-храповики, которые ловят целые классы регрессий. Они
специально неудобные:

| Тест | Что не даёт сделать |
|---|---|
| `test_no_dead_end_screens` | экран бота без единой кнопки — выход только по `/menu` |
| `test_no_new_mutable_globals` | состояние в памяти процесса без ответа «что будет при двух репликах» |
| `test_no_silently_disabled_guards` | отрицательная проверка внутри окна фиксированной длины (сдвинулся код — защита выключилась молча) |
| `test_no_raw_queue_inserts` | постановка операции мимо `operation_bus` — в обход тарифа, предохранителя и дедупа |
| `test_plan_gate_surfaced` | отказ по тарифу, уходящий сырым 500 вместо 403 |
| `test_op_registry_dispatch_parity` | тип операции, объявленный в реестре, но некому исполнять |

## Чего в репозитории больше нет

Удалено 2026-09-04 как дубли и посторонний код. Не возвращайте:

* `platform/` и `nodes-service/` — вторая и третья реализации того же продукта.
  Ни одна не исполняла операции. Решение и обоснование — `docs/adr/0001-one-kernel.md`.
* `basicfood-fixes/`, корневые `main.py`, `orchestrator.py`, `agents/`, `tools/`,
  `src/`, `supabase/`, `database/` — это **BASIC.FOOD**, другой продукт
  (ИИ-агенты магазина зоотоваров). Живёт в ветке `claude/ai-agents-business-LCLnI`.
* корневой `tests/` — 18 тестов вне CI, проверявших текст исходников; пять были
  красными, а «найденная» ими мёртвая кнопка оказалась ложным срабатыванием.

## Правила, которые дороже всего обходятся

* **Операция ставится только через `operation_bus.submit()`.** Прямой INSERT в
  `operation_queue` обходит гейт тарифа, предохранитель Ban Weather и дедуп
  двойного тапа.
* **Исполнитель операций должен быть один.** Лимиты флуда живут в памяти
  процесса; `services/replica_guard.py` предупредит, если реплик больше одной.
  Разносить на `INFRAGRAM_ROLE=web` + `worker` безопасно, два `worker` — нет.
* **Инвайт — самая баноопасная операция продукта.** Любая правка в
  `_exec_mass_invite`, `mass_inviter_engine` или пейсинге проверяется тестами и
  не пушится «на глазок».
* **Миграция — новый `schema_vN.sql`.** Файлы применяются по журналу
  `schema_migrations`, уже применённые пропускаются. Свёртка истории —
  `tg-manager/docs/SCHEMA_CONSOLIDATION_PLAN.md`.
* **Не удалять и не менять существующие миграции** — только ADD COLUMN вперёд.
