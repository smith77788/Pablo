# Дизайн-система мини-аппа и карта разделов

Начато 01.11.2026. Цель — чтобы интерфейс показывал задачу человека, а не
устройство системы, и чтобы новые экраны выглядели одинаково, а правка одного
не ломала соседние.

## 1. Карта разделов — одна на бот и мини-апп

`services/task_sections.py` — единственный источник разделов:

| Ключ | Раздел | Что здесь делают |
|---|---|---|
| `overview` | 📊 Итоги | результат за неделю, операции, позиции |
| `audience` | 👥 Аудитория | собрать людей, база контактов, инвайт |
| `messages` | ✉️ Сообщения | рассылки, публикации, воронки, шаблоны |
| `channels` | 📡 Каналы и боты | создать, оформить, продвинуть |
| `sales` | 💰 Продажи | клиенты, сделки, ИИ-менеджер, оплаты |
| `accounts` | 📱 Аккаунты | аккаунты, прокси, прогрев, защита |
| `settings` | ⚙️ Настройки | тариф, ключи API, пространства |
| `lab` | 🧪 Лаборатория | экспериментальные хабы, скрыты по умолчанию |

По ней собраны:

* **экран «Разделы» мини-аппа** (`#s-more`) — у каждого `.sec`, `.sec-desc` и
  `.mgmt-grid` есть `data-section="<ключ>"`; боковое меню строится из этого
  экрана (`buildDrawer`);
* **главное меню бота** (`botmother_menu._main_menu_kb`) — кнопки разделов
  `BmCb(action="section", sub=<ключ>)`, в каждом быстрые действия в боте и
  кнопка «Открыть раздел в приложении»;
* **диплинк** `#section:<ключ>` — открывает раздел в мини-аппе
  (`runPulseAction` → `openSection`).

**Добавляешь экран** — добавь подпись плитки в `tiles` нужного раздела карты и
плитку в сетку с тем же `data-section`. Расхождение ловит
`tests/test_task_sections_one_map.py`. Новых разделов верхнего уровня не
заводим: если функция не ложится ни в одну задачу — это сигнал, что она для
Лаборатории.

**Лаборатория** выключена по умолчанию: CSS-правило
`#s-more.lab-off:not(.lab-search) [data-section="lab"]` прячет раздел, но его
плитки остаются в разметке (у экрана есть дверь) и находятся поиском.
Включается переключателем внизу экрана «Разделы»; выбор помнит браузер
зрителя (`localStorage['ig_lab_on']`).

Прежнее меню бота по модулям не удалено — оно за кнопкой «🧰 Все инструменты
бота» (`BmCb(action="tools")`).

## 2. Роли оболочек

* **Мини-апп** — полный интерфейс: настройка и работа.
* **Бот** — пульт: «📊 Итоги за неделю», уведомления, статусы операций,
  быстрые действия и двери в мини-апп. Новые сложные мастера в боте не
  заводим — даём кнопку в нужный раздел приложения.

## 3. Токены (`mini_app/ui_kit.css`)

Цвет, отступ, радиус и размер шрифта в новых экранах — только через
`--ui-*`. Новых `#hex` в разметке и в `screens/*.js` не заводим.

| Группа | Токены |
|---|---|
| Отступы (шкала 4px) | `--ui-s1` … `--ui-s6` |
| Радиусы | `--ui-r-sm`, `--ui-r`, `--ui-r-lg` |
| Шрифт | `--ui-fs-xs` 11 · `--ui-fs-sm` 12 · `--ui-fs` 14 · `--ui-fs-lg` 17 · `--ui-fs-xl` 22 |
| Поверхности | `--ui-surface`, `--ui-surface-2`, `--ui-line` |
| Текст | `--ui-text`, `--ui-muted`, `--ui-accent` |
| Смысл | `--ui-good`, `--ui-warn`, `--ui-bad`, `--ui-info` |

Токены построены поверх палитры `:root` из `index.html`, поэтому смена палитры
(и будущая светлая тема по теме Telegram) меняет и компоненты.

## 4. Компоненты (`mini_app/screens/ui_kit.js`)

Каждый компонент — чистая функция «данные → HTML» и класс `.ui-<имя>`:

| Функция | Что рисует |
|---|---|
| `UI.block(title, html, link?)` | блок с заголовком и ссылкой справа |
| `UI.stats([...])` / `UI.stat({...})` | показатель: подпись, число, изменение; `value: null` → «нет данных» |
| `UI.alert({severity, title, detail, buttonHtml})` | карточка «требует внимания» |
| `UI.button(label, fn, ...args)` | кнопка действия |
| `UI.sections([...])` | плитки разделов (ведут в `openSection`) |
| `UI.ok(text)` / `UI.empty(text)` | «всё в порядке» / пустое состояние |
| `UI.skeleton(n)` | скелет загрузки |

Правила:

1. Текст из данных — только через `UI.esc` (компоненты делают это сами).
2. Обработчик — имя глобальной функции и простые аргументы (`UI.call`):
   числа и ключи `[a-z0-9_-]`. Код из данных не исполняется.
3. На экране нет `style="…"`: вид живёт в `ui_kit.css`.
4. «Нет данных» и ноль — разные ответы, и выглядят по-разному.

Первый экран на компонентах — «Итоги» (`screens/summary.js`). Дальше —
переносить на них пять главных экранов по одному, начиная с тех, что
трогаются чаще всего.

## 5. «Итоги»

`services/results_summary.py` считает за период (по умолчанию 7 дней) и
сравнивает с прошлым таким же:

* **Деньги** — заказы ИИ-менеджера (`bot_sales_orders`, статусы `confirmed` и
  `done`) по валютам и выигранные сделки CRM (`crm_deals.stage = 'won'`);
* **Лиды** — новые подписчики ботов (`bot_users.first_seen`);
* **Ответы** — входящие сообщения людей (`relay_messages.direction = 'in'`);
* **Охват** — доставлено рассылками (`broadcasts.sent_count`);
* **Требует внимания** — первые три карточки `mini_app_dashboard.attention_items`.

Маршрут `/api/miniapp/summary`, кнопка бота «📊 Итоги за неделю» и строка в
`/start` вернувшегося владельца читают один и тот же расчёт.
