# Анализ разрывов до топ1 — инвайтер, парсер, управление каналами

Развёрнутый разбор «что есть у топовых TG-софтов автоматизации / что есть у нас».
Три категории разрыва:
- **МЁРТВАЯ ШИРИНА** — бэкенд уже умеет, UI не даёт (самый дешёвый выигрыш).
- **ГЛУБИНА** — фича есть, но настроек мало.
- **ШИРИНА** — фичи нет вообще, а у топ-софтов она базовая.

Легенда статуса: ✅ сделано этим проходом · ⏳ следующий проход · 🔲 бэклог.

---

## 1. ИНВАЙТЕР (mass_inviter_engine + _exec_mass_invite)

### Сейчас
- UI: группа-цель, источник (parsed/crm/bot_users), выбор аккаунтов.
- Бэкенд: `invite_batch`, `invite_by_phones`, распределение аудитории по аккаунтам, обработка PeerFlood с переключением аккаунта, `batch_size`.

### Мёртвая ширина (бэкенд умеет, UI молчит)
- `batch_size` — читается из params, в UI нет. ✅
- `invite_by_phones` — инвайт по номерам телефона реализован, но UI даёт только 3 источника-таблицы. ✅ (добавлен источник import_list с телефонами/username/id)
- `source=import_list` — прямой список не поддержан (только 3 таблицы). ✅

### Глубина (мало настроек)
- Темп/задержка между инвайтами — нет. ✅ (pace slow/normal/fast → множитель паузы)
- Лимит инвайтов на аккаунт — нет (ключевая защита: инвайт — самая баноопасная операция). ✅ (per_account_limit — честно «за прогон», не «в день»; дневной — бэклог, нужна привязка к operation_audit)
- Лимит инвайтов за прогон (max_invites) — нет. ✅
- Фильтр аудитории перед инвайтом: только с username / пропустить без username — нет. ⏳
- Дедуп уже приглашённых (кого уже добавляли в эту группу) — нет. ⏳

### Ширина (нет вообще, у топов есть)
- **Мягкий инвайт** — вместо force-add слать в ЛС ссылку-приглашение (в разы безопаснее, обходит «invite privacy»). 🔲 (крупная фича — отдельный проход)
- Инвайт из «своих» контактов (добавить в контакты → инвайт). 🔲
- Авто-остановка при пороге ошибок (X PeerFlood подряд → стоп). ⏳
- Расписание/окна инвайта. 🔲

## 2. ПАРСЕР АУДИТОРИИ (parser.py + parsed_audiences)

### Сейчас
- UI: источник, тип (members/active), лимит.
- Бэкенд: `parse_members`, `parse_active_users(days_back)`, `get_parsed_audience(active_only)`.
- Схема `parsed_audiences` БОГАТАЯ: is_premium, is_bot, is_active, last_seen_days, geo_country/city, phone, имя — **хранится, но не фильтруется** (get_parsed_audience умеет только active_only).

### Мёртвая ширина
- `days_back` для режима «активные» — бэкенд принимает, UI не даёт (хардкод 30). ✅
- Все хранимые измерения (premium/bot/с телефоном/с username/geo) — не фильтруются при просмотре/выгрузке. ✅ (фильтры premium/с username/не бот/активные)

### Глубина
- Экспорт аудитории в CSV — нет. ✅
- Счётчики по срезам (сколько premium / с телефоном / активных) — нет. ✅
- Дедуп между прогонами (кросс-source) — частично (уникальный индекс per source). ⏳

### Ширина (нет вообще)
- Парс **комментаторов** под постами канала (source_type enum это подразумевает, кода нет). 🔲
- Парс **реакций** на посты (enum есть, кода нет). 🔲
- Парс участников группы по **гео-присутствию** (near). 🔲
- Прямой конвейер «парс → инвайт» / «парс → DM» одной кнопкой. ⏳ (частично: DM/инвайт уже умеют брать parsed_audience как источник — нужна связка из экрана парсера)
- Вычитание списков (аудитория A минус B). 🔲

## 3. УПРАВЛЕНИЕ КАНАЛАМИ (account_manager + mini_app_api)

### Сейчас
- UI: пост, закреп, изменить (about/username), назначить админов, убрать, массовые about/username, фабрика.
- Бэкенд `account_manager` умеет ГОРАЗДО больше, чем выведено.

### Мёртвая ширина (бэкенд есть, UI молчит) — крупнейший разрыв из трёх
- `edit_channel_title` — сменить **название** канала. UI даёт только about/username, названия НЕТ. ✅
- `get_channel_invite_link` — сгенерировать/показать **инвайт-ссылку**. ✅
- `get_channel_members` — **список участников** канала. ⏳
- `kick_from_channel` — **кикнуть** участника. ⏳
- `delete_channel` — **удалить** канал (не «убрать из управления», а реально удалить). ⏳ (опасно — с двойным подтверждением, следующий проход)
- `get_full_channel_info` — полная статистика (подписчики/онлайн/описание) — частично выведено.

### Глубина
- Массовые операции: сейчас только about/username. Добавить массовую смену **названия**, массовый **закреп**, массовую **инвайт-ссылку**. ✅ (title в массовые)
- Slow mode, sign messages, скрытие истории — нет (бэкенд-обвязки нет). 🔲

### Ширина (нет вовсе)
- Просмотр/удаление постов канала из приложения. 🔲
- Ротация инвайт-ссылок по расписанию (Invite Link Rotation Wave из вижена). 🔲
- Статистика роста (график подписчиков) — частично есть отдельным экраном.

## Приоритет этого прохода (максимальный охват при корректности)
Инвайтер: batch_size + import_list-источник + pace + дневной лимит/аккаунт + max за прогон.
Парсер: days_back + фильтры (premium/username/не-бот/активные) + счётчики срезов + CSV-экспорт.
Каналы: смена НАЗВАНИЯ (одиночная + массовая) + инвайт-ссылка.

Всё остальное (🔲/⏳) — честно зафиксировано здесь как бэклог до полного топ1, не выдаётся за сделанное.

# Волна 3 — strike, воронки, расписания (2026-07-07)

## 7. STRIKE-ДВИЖОК (strike_engine + _exec_strike)
Движок огромный: пресеты, авто-детект, A/B, эффективность, email/spambot эскалация, эшелонирование волн (plan_waves), preflight по трасту, verify takedown.
### Мёртвая глубина
- `_exec_strike` читает `num_waves` (эшелонирование), `preset` — UI шлёт только {target, category}, волны/интенсивность недоступны. ✅ (num_waves + лимит аккаунтов в UI)
### Ширина (бэклог)
- Выбор конкретных аккаунтов под strike (сейчас все активные до 50). ⏳
- Verify takedown из UI (проверка, снят ли таргет). 🔲
- Email-эскалация как опция в UI. 🔲

## 8. ВОРОНКИ (funnels + funnel_steps)
### Мёртвая ширина — крупнейшая волны
- `funnel_steps` (multi-step drip с delay_minutes) + движок подписок (funnel_subscriptions.current_step/next_send_at) есть, но `create_funnel` вставляет ТОЛЬКО шаг 1, а эндпоинта добавить шаг НЕТ. Воронка застряла на одном сообщении. ✅ (add/delete шага + delay в UI)
### Ширина (бэклог)
- Условные переходы (если нажал кнопку → ветка). 🔲
- Кнопки/медиа в шагах. 🔲
- Аналитика прохождения по шагам. ⏳

## 9. РАСПИСАНИЯ/ПУБЛИКАЦИЯ (scheduler + scheduled_broadcasts)
### Сейчас: одноразовый бродкаст в момент execute_at.
### Ширина
- **Повторяемость** (ежедневно/еженедельно) — нет (только one-shot). ✅ (repeat_interval + перезапись следующего в runner)
- Медиа в отложенном посте — нет. 🔲
- Окна тихих часов / таймзона. 🔲

## Приоритет волны 3
Strike: num_waves + лимит аккаунтов. Воронки: управление шагами (add/delete + delay). Расписания: повторяемость.
