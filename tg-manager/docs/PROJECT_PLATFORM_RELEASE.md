# Infragram. Требования к большому выпуску

## Пользователи и рабочее место

Выпуск обслуживает владельцев отдельных ресурсов, операторов больших парков, команды и агентства. Стартовый экран показывает все проекты и проблемы. Проект — гибкая папка с ресурсами, сценариями и журналом. Создать её можно из импорта, шаблона, вручную или по плану, предложенному ИИ. Найденные при синхронизации ресурсы попадают в общий каталог. Один канал или бот может использоваться в нескольких проектах. Основные настройки изменяются через управляющий проект. Роль назначается на проект с исключениями по ресурсам.

## Действия и сценарии

Расширяем существующие network_builder, operation_bus и workflow_runtime. Действие использует один контракт для ручного запуска и сценария. Он описывает входы, допустимые ресурсы, проверку прав, предпросмотр, результат по цели и безопасный повтор. При подготовке каждого запуска оператор выбирает способ назначения исполнителя. Фильтры, теги, пулы, поиск, импорт, дедупликация, доступность и балансировка должны работать вместе. Автоматический подбор допускает ручную замену.

На телефоне предлагается редактор из карточек «Когда → С чем → Что сделать → Что делать при сбое». Сложные ветки раскрываются по месту, карта показывает их обзор. Начальные триггеры — расписание, событие Telegram, итог операции и подписанный вебхук. Первый комплект шаблонов включает городскую сеть, контент и согласования, поддержку, модерацию и уведомления. Для повторов выбираются фиксированные цели или новое вычисление по правилам. Политики недостатка доступных ресурсов и частичных сбоев задаёт пользователь в сценарии.

ИИ ищет действия, объясняет настройки, создаёт черновики, предлагает улучшения и запускает разрешённые действия через тот же контракт. Каждое внешнее действие высокого риска требует подтверждения с привязкой к параметрам и целям. Расширения используют изолированные полномочия, отдельные секреты и проверку доступа по проекту и ресурсу. Готовность расширений проверяется негативными тестами доступа к чужим данным.

## Контекстное меню ресурсов

Действия доступны рядом с ресурсом через кнопку «⋯», длительное нажатие на телефоне и правый клик на компьютере. В первом уровне видны частые команды с текстовыми подписями. В «Все действия» находятся редкие команды и изменения состава проекта. Меню показывает текущий объект или число выбранных объектов и использует единый контракт действий для проверки применимости.

Первое подключение — узлы сети проекта для участников пилота (INFRAGRAM_PROJECT_PILOT_IDS). Меню открывает существующие карточки профиля, бота, канала и группы, копирует ID привязанного объекта, открывает диалоги профиля и команды бота и позволяет убрать узел из проекта с подтверждением. Узел шаблона без привязки показывает только применимые действия. Убрать узел означает удалить связь с проектом, ресурс в Telegram сохраняется.

В том же большом выпуске подключаем меню к общему каталогу, карточкам и массовой выборке. Для выборки каждая команда показывает, скольким целям она доступна и почему часть не подходит. Из команды можно открыть предпросмотр запуска, передать текущий объект в редактор сценария или сохранить параметры как шаблон. Права и подтверждения проверяются общим серверным путём, включая запуск через ИИ. В приёмку входят управление с телефона и клавиатуры, отмена долгого нажатия при прокрутке, проверка прав и сохранение точного набора целей.

### Подключение ресурсов из каталога

В пилоте проект позволяет найти свои аккаунты, ботов, каналы и группы по названию, username или ID. Форма сохраняет ввод ID вручную. Подключение проверяет владельца и тип ресурса, повтор возвращает существующий узел. Один ресурс может оставаться в нескольких проектах. Рёбра разрешены только между узлами одной сети. Контекстная отвязка удаляет собственные рёбра вместе с узлом, сохраняет каталог и другие проекты, откладывается во время активной операции проекта. Устаревшая привязка помечается как недоступная. Контекстная публикация сохраняет точный 64-битный ID до очереди. Развёртывание блокирует отвязку из меню и из отчёта. Отвязка из меню аннулирует ранее подтверждённый план очистки для той же цели.

## Очистка ресурсов из результатов проверки

Ближайшая итерация связывает результаты проверки ограничений, каталог и контекстное меню. В карточке завершённой проверки открыть «Управлять найденными» и дать выбрать одну, несколько или весь подтверждённый срез. Загрузить результаты именно этой операции, включая цели за пределами первой страницы журнала. Показать отдельно «Недоступен», «Ограничен», «Скрыт из поиска» и «Не удалось проверить». Скрытие из поиска и ошибка проверки не являются подтверждением блокировки. Ничего не выбирать автоматически.

- «Убрать из проекта» снимает привязку только в выбранном проекте. Сущность остаётся в каталоге и в других проектах.
- «Отключить в Infragram» прекращает управление выбранными ресурсами в приложении. Использовать существующие механизмы скрытия и восстановления, сохранить историю, исключить повторное подключение при импорте. Для ботов проверить различие между одиночным мягким отключением и текущим пакетным физическим удалением записи.
- Перед подтверждением показать действие, точный набор целей, затронутые проекты и влияние на активные сценарии. При выполнении проверять владельца, право действия и актуальность целей. Показывать реальные итоги по каждой цели, включая уже отключённые и пропущенные. Удаление в Telegram вынесено в отдельную явно подтверждаемую команду.
- Проверить завершённую операцию после перезапуска. Старое уведомление ожидания не должно отображаться как текущая ошибка, а фактические терминальные ошибки должны оставаться видимыми.

Приёмка на синтетическом наборе из 295 целей по структуре операции №843: выбор результатов из разных страниц, отсутствие расширения пустого среза, изоляция владельцев и проектов, повтор без дублей, частичный результат, сохранение истории, повторный импорт и восстановление. Дополнительно проверить, что очередь и сценарии не используют отключённую цель и что соседние проекты сохраняют ресурс после локальной отвязки.

### Удаление в Telegram и ёмкость аккаунтов

- В результатах проверки предложить «Удалить в Telegram» только для ресурсов, которыми пользователь вправе распоряжаться. Каналы и группы проводить через существующую очередь и исполнитель удаления. Для ботов использовать подтверждение владельца через BotFather и сверку результата. Показать точный ID, аккаунт-владелец, последствия для проектов и сценариев. Заблокированный или скрытый ресурс сам по себе не доказывает доступность удаления.
- Отдельно предложить «Снять публичный юзернейм» для канала или супергруппы, если нужно сохранить сам объект. Перед удалением сверять стабильный ID, поскольку username может перейти к другой сущности. При тайм-ауте отметить «требуется сверка» и не повторять вслепую.
- В карточке каждого аккаунта показывать доступность назначения публичного юзернейма каналу или супергруппе по ответу Telegram. Различать «доступно», «достигнут лимит» и «не удалось проверить». Проверять до развёртывания, обновлять после подтверждённого удаления или снятия имени и показывать время проверки. Не обещать точное число оставшихся мест без надёжных данных. Ограничения создания ботов и каналов учитывать отдельно.
- Приёмка: повторное назначение username другому объекту, отзыв прав, недоступный ресурс, FloodWait, разрыв связи после запроса, частичный итог и повторная сверка ёмкости без пробного создания новых ресурсов.

## Приёмка и выпуск

Предпросмотр показывает краткий итог, конкретные цели, исполнителей, причины недоступности и ожидаемые изменения. Журнал различает выбранные, допущенные, отложенные и выполненные цели, показывает причины, историю и действия команды. Перезапуск и частичный сбой сохраняют прогресс и исключают слепой повтор действия с неизвестным исходом.

На одном сценарии с 1 000 профилей проверяем скорость интерфейса и поиска, объяснимость результата по каждой цели и восстановление после сбоя без дублей. Для сравнения с конкурентами используем одинаковые пользовательские сценарии и замеряем время, число действий, успешность и восстановление. Все заявленные направления входят в один выпуск. Сначала доступ получают владелец и тестовая команда. Живые прогоны проводятся на разрешённых тестовых ресурсах.

## Текущее подключение

Экран существующей сети открывает редактор публикаций с каналами этой сети. Команда «Подготовить публикацию» из контекстного меню канала открывает тот же редактор с одним адресатом. Сервер сверяет подтверждённый список и владелец может выбрать время через существующий планировщик. Очередь повторно проверяет принадлежность каналов перед исполнением. Вход доступен через INFRAGRAM_PROJECT_PILOT_IDS, список Telegram ID через запятую. По умолчанию список пуст.

### Журнал проекта

В пилоте журнал открывается из сети проекта и использует экран операций. Публикации с project_id и существующие развёртывания с instance_id показываются в одной истории. Список, счётчики, типы и экспорт CSV/JSON ограничены проектом и владельцем. Поиск, статус и период применяются к списку. Экспорт выгружает историю проекта целиком в пределах существующего лимита выгрузки. Карточка операции показывает номер проекта и сохраняет доступ к журналу целей.

Проверка из tg-manager на отдельной тестовой БД: `INFRAGRAM_TEST_DSN=<dsn> python -m pytest -q tests/test_project_operations_postgres.py tests/test_the_operation_card_says_what_was_launched.py tests/test_the_operations_list_filters_and_acts_in_bulk.py`. Проверяются второй проект владельца, чужой владелец, запрос вне пилота, старое развёртывание, пагинация, фильтры и выгрузка. Тестовый PostgreSQL использует временные таблицы. Telegram не вызывается.

Откат: отключить пилот через INFRAGRAM_PROJECT_PILOT_IDS или откатить коммит. Миграций нет, параметры уже поставленных операций сохраняются. Нагрузочные замеры, мобильный прогон и ролевой доступ к журналу команды остаются открытыми.

### Проверка очистки ресурсов

В пилоте карточка конкретной завершённой проверки открывает список находок с фильтром по четырём вердиктам. Старый отчёт использует сохранённые ID и предупреждает о неполном списке. «Убрать из проекта» удаляет узлы и их связи только в выбранном проекте. «Отключить в Infragram» ставит бота на паузу или переносит канал либо группу с одной привязкой в существующий список восстановления. Для отключения ресурса сначала снимаются проектные привязки. Активные сценарии бота и уже запущенные публикации могут блокировать действие. Подтверждение действует 10 минут и требует нового предпросмотра при изменении плана.

В карточке аккаунта участник пилота может вручную запросить у Telegram доступность публичного юзернейма для каналов и супергрупп. Приложение показывает результат и время проверки. Занятая сессия пропускается. Автоматическое обновление после освобождения юзернейма и проверка перед развёртыванием остаются в плане. Удаление канала в существующем исполнителе использует стабильный ID. Отдельные команды удаления в Telegram и снятия юзернейма из результатов проверки остаются в плане.

Полный и частичный импорт, в том числе запуск из нативного бота, используют общий каталог с транзакционной блокировкой на владельца. Импорт пропускает отключённые ресурсы и показывает их отдельно в результате. Явное подключение по ссылке снимает отметку отключения вместе с записью каталога. Новая миграция сохраняет ID строки, дату подключения, роли и статистику при отключении. Старые записи восстанавливаются с доступными метаданными. Список восстановления дополнительно передаёт точный строковый ID. Виртуальный администратор после восстановления остаётся выключенным до явного включения.

Одиночное, пакетное удаление и очистка неактуальных ботов сохраняют аудиторию и историю. Очистка после проверки пропускает бота, если токен поменялся или бот на паузе из отчёта. У автоматической очистки сохраняются отдельные счётчики обнаруженных, фактически убранных и изменившихся после проверки. Сетевое исключение Bot API записывается по типу без URL и токена.

При паузе бота по результатам проверки карточка сохраняет доступ к истории и локальным настройкам. Внешние команды, профиль, аватар, вебхук и локализация требуют активного бота. После архивирования прямые ссылки на карточку, классические воронки, аудиторию и настройки закрываются. Восстановление возвращает сохранённые данные. Архивирование отменяет ожидающие расписания и уже подготовленные рассылки из расписаний, сохраняя строки истории. Ручные рассылки имеют отдельный жизненный цикл.
