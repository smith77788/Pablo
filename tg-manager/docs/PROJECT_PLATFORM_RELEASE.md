# Infragram. Требования к большому выпуску

## Пользователи и рабочее место

Выпуск обслуживает владельцев отдельных ресурсов, операторов больших парков, команды и агентства. Стартовый экран показывает все проекты и проблемы. Проект — гибкая папка с ресурсами, сценариями и журналом. Создать её можно из импорта, шаблона, вручную или по плану, предложенному ИИ. Найденные при синхронизации ресурсы попадают в общий каталог. Один канал или бот может использоваться в нескольких проектах. Основные настройки изменяются через управляющий проект. Роль назначается на проект с исключениями по ресурсам.

### Стартовый обзор проектов

Участник пилота при входе видит до пяти проектов, сначала с недоступными привязками или сбоями за семь дней. Карточка ведёт в топологию, журнал проекта и проблемную операцию. Остальные проекты доступны через полный список. Счётчик недоступных привязок сравнивает узлы с каталогом владельца. Он измеряет наличие связи с каталогом. Незавершённые операции учитываются независимо от даты, завершённые с ошибками — по времени завершения. Отказ одного запроса не блокирует остальные блоки главной.

## Действия и сценарии

Расширяем существующие network_builder, operation_bus и workflow_runtime. Действие использует один контракт для ручного запуска и сценария. Он описывает входы, допустимые ресурсы, проверку прав, предпросмотр, результат по цели и безопасный повтор. При подготовке каждого запуска оператор выбирает способ назначения исполнителя. Фильтры, теги, пулы, поиск, импорт, дедупликация, доступность и балансировка должны работать вместе. Автоматический подбор допускает ручную замену.

На телефоне предлагается редактор из карточек «Когда → С чем → Что сделать → Что делать при сбое». Сложные ветки раскрываются по месту, карта показывает их обзор. Начальные триггеры — расписание, событие Telegram, итог операции и подписанный вебхук. Первый комплект шаблонов включает городскую сеть, контент и согласования, поддержку, модерацию и уведомления. Для повторов выбираются фиксированные цели или новое вычисление по правилам. Политики недостатка доступных ресурсов и частичных сбоев задаёт пользователь в сценарии.

ИИ ищет действия, объясняет настройки, создаёт черновики, предлагает улучшения и запускает разрешённые действия через тот же контракт. Каждое внешнее действие высокого риска требует подтверждения с привязкой к параметрам и целям. Расширения используют изолированные полномочия, отдельные секреты и проверку доступа по проекту и ресурсу. Готовность расширений проверяется негативными тестами доступа к чужим данным.

## Контекстное меню ресурсов

Действия доступны рядом с ресурсом через кнопку «⋯», длительное нажатие на телефоне и правый клик на компьютере. В первом уровне видны частые команды с текстовыми подписями. В «Все действия» находятся редкие команды и изменения состава проекта. Меню показывает текущий объект или число выбранных объектов и использует единый контракт действий для проверки применимости.

Меню доступно всем пользователям на узлах их проектов. Меню открывает существующие карточки профиля, бота, канала и группы, копирует ID привязанного объекта, открывает диалоги профиля и команды бота и позволяет убрать узел из проекта с подтверждением. Узел шаблона без привязки показывает только применимые действия. Убрать узел означает удалить связь с проектом, ресурс в Telegram сохраняется.

Меню доступно в списках и карточках аккаунтов, ботов, каналов и чатов, включая таблицу аккаунтов. Частые команды вынесены наверх. В длинных меню есть поиск по командам и группам. Для публичного @имени доступны копирование ссылки и переход в Telegram. Аккаунт даёт доступ к профилю, диалогам, сеансам, связанным каналам, заметке и меткам. Бот владельца даёт доступ к профилю, командам, паузе и удалению из Infragram. В карточке канала различаются удаление в Telegram, выход и удаление из Infragram. Меню проекта открывает журнал, добавление и связывание узлов, просмотр плана. Меню открывается кнопкой «⋯», а в списках также долгим касанием, правым кликом и Shift+F10. Движение пальца отменяет долгое касание.

В списках аккаунтов, ботов и каналов с чатами есть «Действия с выбранными». Меню показывает объём выбора, копирует точные ID фиксированной выборки и открывает существующие команды профиля, публикации, тегов, пулов и очистки. Для всего серверного среза аккаунтов фиксируются параметры фильтра. Состав среза определяется сервером при выполнении запроса. Счётчики применимости отдельных команд, единый предпросмотр, передача в сценарий или шаблон остаются в плане.

Приёмка меню. Проверяются поиск, роли канала, активные и общие боты, отмена долгого касания, устаревший ответ карточки, смена выбора и неизменность цели между открытием формы, подтверждением и отправкой массового поста. Подписанный HTTP на тестовом PostgreSQL проверяет каталоги, привязку, журнал и чужие ресурсы. Меню использует прежние маршруты без миграций. Мобильный браузерный проход, общие командные роли и нагрузочные замеры открыты. Вызовы Telegram подменяются в тестах.

```sh
INFRAGRAM_TEST_DSN=<dsn> python -m pytest -q -o addopts= tests/test_project_resource_actions.py tests/test_project_catalog_postgres.py tests/test_project_operations_postgres.py tests/test_archived_bot_access_postgres.py tests/test_fleet_tools.py tests/test_long_account_list_is_not_redrawn.py tests/test_accounts_pagination.py tests/test_miniapp_routes_are_not_lost.py tests/test_no_duplicate_definitions.py tests/test_innerhtml_interpolations_are_escaped.py tests/test_every_query_with_an_url_id_takes_the_owner.py
```

### Подключение ресурсов из каталога

В пилоте проект позволяет найти свои аккаунты, ботов, каналы и группы по названию, username или ID. Форма сохраняет ввод ID вручную. Подключение проверяет владельца и тип ресурса, повтор возвращает существующий узел. Один ресурс может оставаться в нескольких проектах. Рёбра разрешены только между узлами одной сети. Контекстная отвязка удаляет собственные рёбра вместе с узлом, сохраняет каталог и другие проекты, откладывается во время активной операции проекта. Устаревшая привязка помечается как недоступная. Контекстная публикация сохраняет точный 64-битный ID до очереди. Развёртывание блокирует отвязку из меню и из отчёта. Отвязка из меню аннулирует ранее подтверждённый план очистки для той же цели.

## Очистка ресурсов из результатов проверки

Ближайшая итерация связывает результаты проверки ограничений, каталог и контекстное меню. В карточке завершённой проверки открыть «Управлять найденными» и дать выбрать одну, несколько или весь подтверждённый срез. Загрузить результаты именно этой операции, включая цели за пределами первой страницы журнала. Показать отдельно «Недоступен», «Ограничен», «Скрыт из поиска» и «Не удалось проверить». Скрытие из поиска и ошибка проверки не являются подтверждением блокировки. Ничего не выбирать автоматически.

- «Убрать из проекта» снимает привязку только в выбранном проекте. Сущность остаётся в каталоге и в других проектах.
- «Отключить в Infragram» прекращает управление выбранными ресурсами в приложении. Использовать существующие механизмы скрытия и восстановления, сохранить историю, исключить повторное подключение при импорте. Для ботов проверить различие между одиночным мягким отключением и текущим пакетным физическим удалением записи.

### Сохранённый итог очистки после повторного входа

Карточка завершённой проверки показывает сохранённые применения в отдельном разделе. Можно снова открыть исходный список изменённых и пропущенных целей с их причинами, включая вариант после восстановления ресурса. Чтение использует существующий маршрут отчёта и выполняется без исходного подтверждения. Сервер проверяет флаг пилота, владельца, ID проверки и ID сохранённого итога. ### Удаление в Telegram и ёмкость аккаунтов

- В результатах проверки предложить «Удалить в Telegram» только для ресурсов, которыми пользователь вправе распоряжаться. Каналы и группы проводить через существующую очередь и исполнитель удаления. Для ботов использовать подтверждение владельца через BotFather и сверку результата. Показать точный ID, аккаунт-владелец, последствия для проектов и сценариев. Заблокированный или скрытый ресурс сам по себе не доказывает доступность удаления.
- Отдельно предложить «Снять публичный юзернейм» для канала или супергруппы, если нужно сохранить сам объект. Перед удалением сверять стабильный ID, поскольку username может перейти к другой сущности. При тайм-ауте отметить «требуется сверка» и не повторять вслепую.
- В карточке каждого аккаунта показывать доступность назначения публичного юзернейма каналу или супергруппе по ответу Telegram. Различать «доступно», «достигнут лимит» и «не удалось проверить». ## Приёмка и выпуск

Предпросмотр показывает краткий итог, конкретные цели, исполнителей, причины недоступности и ожидаемые изменения. Журнал различает выбранные, допущенные, отложенные и выполненные цели, показывает причины, историю и действия команды. Перезапуск и частичный сбой сохраняют прогресс и исключают слепой повтор действия с неизвестным исходом.

На одном сценарии с 1 000 профилей проверяем скорость интерфейса и поиска, объяснимость результата по каждой цели и восстановление после сбоя без дублей. Для сравнения с конкурентами используем одинаковые пользовательские сценарии и замеряем время, число действий, успешность и восстановление. Все заявленные направления входят в один выпуск. Сначала доступ получают владелец и тестовая команда. Живые прогоны проводятся на разрешённых тестовых ресурсах.

## Текущее подключение

Экран существующей сети открывает редактор публикаций с каналами этой сети. Команда «Подготовить публикацию» из контекстного меню канала открывает тот же редактор с одним адресатом. Сервер сверяет подтверждённый список и владелец может выбрать время через существующий планировщик. Очередь повторно проверяет принадлежность каналов перед исполнением. Вход доступен через INFRAGRAM_PROJECT_PILOT_IDS, список Telegram ID через запятую. По умолчанию список пуст.

### Подтверждение развёртывания проекта

Пилот использует существующие планировщик топологии, выбор аккаунта, шину и исполнитель. Подтверждение действует 10 минут и связывает проект, точную топологию и исполнителя. ### Проверка очистки ресурсов

В пилоте карточка конкретной завершённой проверки открывает список находок с фильтром по четырём вердиктам. Старый отчёт использует сохранённые ID и предупреждает о неполном списке. «Убрать из проекта» удаляет узлы и их связи только в выбранном проекте. «Отключить в Infragram» ставит бота на паузу или переносит канал либо группу с одной привязкой в существующий список восстановления. Для отключения ресурса сначала снимаются проектные привязки. Активные сценарии бота и уже запущенные публикации могут блокировать действие. Подтверждение действует 10 минут и требует нового предпросмотра при изменении плана.

Форма открывается с действием «Отключить в Infragram». Для отвязки при нескольких проектах форма явно просит выбрать проект. Если подходящих целей нет, она объясняет это рядом со списком. Выбор сохраняется при поиске по названию или точному строковому ID, переключении вердикта и переходе между страницами. Список рисует до 40 ресурсов на страницу. Команда массового выбора действует на доступные цели всего текущего фильтра, включая другие страницы, и соблюдает предел предпросмотра. Пустой результат поиска не добавляет целей. Смена действия или проекта очищает выбор, а общий счётчик показывает отмеченные цели вне текущего фильтра. При повторном открытии отчёта видны последние 50 успешных действий с точным ID цели, проектом и временем. История читается из существующего аудита в одном снимке с отчётом. Служебные версии строк и привязки аккаунтов остаются внутри подписываемого плана на сервере.

Отключённые владельцем каналы и группы остаются в исходном отчёте со своим вердиктом и пометкой «Ресурс уже отключён в Infragram». Повторный импорт сохраняет пометку. Из отчёта и результата отключения можно открыть существующий список восстановления каналов и групп. После отключения бота результат ведёт в его настройки по точному ID. После явного восстановления отчёт снова позволяет управлять ресурсом. Повторный предпросмотр отключённой цели возвращает причину пропуска. Совместимый маршрут принимает только активные ресурсы с вердиктом «Недоступен».

При исчезновении ресурса из каталога отчёт сохраняет его ID, исходный вердикт и причину проверки. Список показывает доступные связи с проектами отдельно от состояния каталога. Если связей нет, историческая строка доступна для поиска, а её выбор для отвязки и отключения заблокирован. Состояние и названия из чужого каталога не участвуют в ответе. Прямой запрос предпросмотра показывает такие цели как пропущенные. Для полностью пропущенного плана сервер возвращает `token: null`. Запрос с `preview: true` и подписью отклоняется до изменения данных. В смешанном плане применяются только готовые цели, а исторические строки остаются доступны после повторного чтения. Миграций нет. Подтверждения для затронутых планов, сформированные до обновления, могут потребовать нового предпросмотра.

«Управлять найденными» из каталога открывает форму для ID последней проверки. Из карточки «Уборка по итогам проверки» открывает форму для ID текущей проверки. Возврат из предпросмотра и ошибка его загрузки сохраняют выбор. После ошибки подтверждения сначала обновляется отчёт. Форма показывает точные ID. Ресурс, исчезнувший из каталога, остаётся доступен для отвязки при наличии связи в проекте владельца. Список восстановления предлагается только при сохранённой записи об отключении. Подписанный HTTP-тест проверяет старую связь, сохранение соседнего проекта и отказ повторного подтверждения.

Из «Защиты аккаунтов» форма также открывается по ID последней проверки. Перед выбором показана область действия, в предпросмотре видны количества готовых и пропущенных целей. При очистке учитываются оба формата целей публикации. `mass_publish` и `quick_post` используют Telegram ID, `bulk_post_chans` использует ID строки каталога. Явный пустой список целей публикации не блокирует очистку, а публикация без списка целей может её заблокировать.

Отключение из отчёта проверяет и текущие задания `bulk_chan_exec`. Если воркер уже захватил команду для той же пары «канал или группа ↔ аккаунт», предпросмотр объясняет, почему нужно дождаться её завершения. Захват воркером между предпросмотром и подтверждением требует нового предпросмотра. Команда для другого аккаунта или ресурса не блокирует отключение. При отвязке продолжают действовать проверки проектных операций.

Воркер `bulk_chan_exec` повторно сверяет пары с каталогом владельца. Старые задания со строковыми ID поддерживаются. Отключённые, перепривязанные и чужие цели пропускаются с причиной по точному ID, а доступные цели продолжают исполнение. Повтор учитывает сохранённые успехи и причины пропуска. Для названия, описания, очистки постов и выхода ответ Telegram при разрешении username сверяется с ожидаемым ID. При наличии access hash запрос находит сущность по ID. Удаление в Telegram использует действующее отдельное подтверждение. Миграций нет.

Синтетический прогон использует реальные HTTP-маршруты Mini App, PostgreSQL и диспетчер очереди. Вызов Telegram имитируется. Два варианта сверяют подписанное отключение и смену привязки между предпросмотром и применением. Оба проверяют чужую цель, выполнение соседней цели, частичный итог в карточке, журнал, отказ в чтении чужого журнала и повтор без сетевого вызова. Отдельный тест блокирует подтверждение на транзакции захвата и проверяет конфликт после её завершения. Тест повторного импорта отличает удаление технической записи с причиной `gone` от удаления активной записи или отметки владельца об отключении.

Публикация проекта повторно проверяет пилот, формат и принадлежность точного набора до редактора и подготовки отправки. Отвязка из завершённой проверки останавливает ожидающее задание целиком, если изначальная цель больше недоступна. Новый канал в проекте не добавляется к уже подтверждённому заданию. Предпросмотр отклоняет повторяющиеся параметры проекта и канала, а также фильтр по каналу без проекта. Отложенная публикация в тесте сохраняется в очереди PostgreSQL, повторный подписанный запрос возвращает тот же ID, а штатный диспетчер записывает отказ или успех в карточку. Telegram и уведомления имитируются. Штатный поллер оставляет будущую операцию в очереди и забирает наступившую ровно один раз между двумя параллельными тиками. Смещение времени +05:45 сверено с той же точкой UTC. Валидный круг ставит следующий с исходными целями. Отвязка, отзыв пилота и недействительный выбор останавливают расписание с причиной в карточке. Восстановитель после рестарта пропускает этот результат, даже если цель снова доступна.

При остановке из-за изменения области одиночный и массовый повтор в Mini App, форма копии и повтор нативного бота требуют нового предпросмотра. Шина сверяет точный ID операции, владельца, проект, исходный список и текущее наличие целей перед постановкой производного задания. Новый запуск проходит штатный предпросмотр и повторное подтверждение списка. Старый результат с причиной остановки расписания поддерживается. Карточка, список операций и уведомление о завершении убирают команды повтора у такого результата. Карточка объясняет необходимость нового предпросмотра и открывает только исходный проект, если доступ к пилоту и владение проектом подтверждены. Для удаления проекта или отзыва доступа карточка показывает причину без ссылки. Переход не ставит публикацию в очередь. Подписанный HTTP проверяет состояние карточки и списка, Node выполняет рендер и обработчик перехода на синтетическом ответе. Проверены восстановление цели после отказа, свежий запуск, допустимый поднабор, добавление канала сверх исходного списка и подмена владельца.

Предпросмотр показывает исходный вердикт и отдельно причину пропуска. Подтверждение привязано к версиям выбранных узлов и затронутых рёбер, включая правки, при которых их ID сохраняются. Версии строк остаются на сервере. Подпись, владелец, срок и назначение подтверждения проверяются до транзакции. Внутри транзакции проверяются доступ к пилоту и актуальность плана. Подтверждение, выданное прежней версией приложения, может потребовать нового предпросмотра.

«Только выбранные» показывает все отмеченные ресурсы, в том числе скрытые поиском и фильтром вердикта. В этом списке можно точечно снять отметку. Возврат к полному списку возвращает предыдущий поиск и фильтр. Предпросмотр и итог выводят до 40 строк на страницу и позволяют искать по названию или точному ID и отбирать цели по исходу действия. В предпросмотре фокус уходит на сводку. Число рядом с «Подтвердить» показывает размер готового набора, даже если фильтр сейчас показывает только пропущенные строки. Фильтры на этапах предпросмотра и итога служат для просмотра. Подтверждение отправляет исходный набор и подпись. В итоге видны вердикт проверки и отдельный исход действия. У подтверждённого отключения доступен переход к восстановлению конкретного канала или группы либо в настройки бота. В сохранённом результате после повтора для актуального восстановления нужно обновить отчёт.

Если ответ потерялся после записи, то же действующее подтверждение возвращает сохранённый результат. Запись результата, изменение ресурсов и аудит проходят одной транзакцией. Результат привязан к владельцу, проверке, действию, проекту и точному набору целей. Повтор возвращает исторический результат даже после восстановления ресурса и не отключает его повторно. После истечения срока подтверждения результат можно сверить по истории отчёта. Миграция `373` добавляет таблицу результатов, которую при откате приложения можно оставить.

Из отчёта можно открыть восстановление конкретного канала или группы по точному строковому ID. При нескольких отключённых целях интерфейс предлагает выбор ресурса. Фильтр применяется на сервере до лимита общего списка и ограничен владельцем. Повторное чтение сохранённого результата предлагает обновить отчёт для актуальных действий. Тест с 501 более свежей записью подтверждает, что старый ресурс можно найти и восстановить отдельно.

При восстановлении проверка тарифа, возврат ресурса и запись общего журнала проходят под блокировкой каталога в одной транзакции. Если два запроса одного владельца претендуют на последнее место, один получает отказ по лимиту. При ошибке записи журнала ресурс остаётся в списке восстановления. Старые записи без привязки к аккаунту отображаются с причиной недоступности восстановления. Нативный фильтр импорта сохраняет отметку «Недоступен в Telegram» при отказе по квоте. Отметка снимается вместе с успешной записью вновь найденного ресурса. Отметка отключения владельцем сохраняется.

Восстановление канала или группы требует сохранённой привязки к активному аккаунту владельца с непустой сессией. Отчёт и список восстановления показывают причину недоступности отдельно от вердикта проверки. POST проверяет аккаунт под блокировкой в той же транзакции, что перенос из архива и запись аудита. При отключённом, чужом, удалённом аккаунте либо пустой сессии архив сохраняется, пассивный импорт ресурс не возвращает.
