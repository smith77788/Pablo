# Infragram. Требования к большому выпуску

## Пользователи и рабочее место

Выпуск обслуживает владельцев отдельных ресурсов, операторов больших парков, команды и агентства. Стартовый экран показывает все проекты и проблемы. Проект — гибкая папка с ресурсами, сценариями и журналом. Создать её можно из импорта, шаблона, вручную или по плану, предложенному ИИ. Найденные при синхронизации ресурсы попадают в общий каталог. Один канал или бот может использоваться в нескольких проектах. Основные настройки изменяются через управляющий проект. Роль назначается на проект с исключениями по ресурсам.

## Действия и сценарии

Расширяем существующие network_builder, operation_bus и workflow_runtime. Действие использует один контракт для ручного запуска и сценария. Он описывает входы, допустимые ресурсы, проверку прав, предпросмотр, результат по цели и безопасный повтор. При подготовке каждого запуска оператор выбирает способ назначения исполнителя. Фильтры, теги, пулы, поиск, импорт, дедупликация, доступность и балансировка должны работать вместе. Автоматический подбор допускает ручную замену.

На телефоне предлагается редактор из карточек «Когда → С чем → Что сделать → Что делать при сбое». Сложные ветки раскрываются по месту, карта показывает их обзор. Начальные триггеры — расписание, событие Telegram, итог операции и подписанный вебхук. Первый комплект шаблонов включает городскую сеть, контент и согласования, поддержку, модерацию и уведомления. Для повторов выбираются фиксированные цели или новое вычисление по правилам. Политики недостатка доступных ресурсов и частичных сбоев задаёт пользователь в сценарии.

ИИ ищет действия, объясняет настройки, создаёт черновики, предлагает улучшения и запускает разрешённые действия через тот же контракт. Каждое внешнее действие высокого риска требует подтверждения с привязкой к параметрам и целям. Расширения используют изолированные полномочия, отдельные секреты и проверку доступа по проекту и ресурсу. Готовность расширений проверяется негативными тестами доступа к чужим данным.

## Контекстное меню ресурсов

Действия доступны рядом с ресурсом через кнопку «⋯», длительное нажатие на телефоне и правый клик на компьютере. В первом уровне видны частые команды с текстовыми подписями. В «Все действия» находятся редкие команды и изменения состава проекта. Меню показывает текущий объект или число выбранных объектов и использует единый контракт действий для проверки применимости.

Первое подключение — узлы сети проекта для участников пилота (INFRAGRAM_PROJECT_PILOT_IDS). Меню открывает существующие карточки профиля, бота, канала и группы, копирует ID привязанного объекта, открывает диалоги профиля и команды бота и позволяет убрать узел из проекта с подтверждением. Узел шаблона без привязки показывает только применимые действия. Убрать узел означает удалить связь с проектом, ресурс в Telegram сохраняется.

В том же большом выпуске подключаем меню к общему каталогу, карточкам и массовой выборке. Для выборки каждая команда показывает, скольким целям она доступна и почему часть не подходит. Из команды можно открыть предпросмотр запуска, передать текущий объект в редактор сценария или сохранить параметры как шаблон. Права и подтверждения проверяются общим серверным путём, включая запуск через ИИ. В приёмку входят управление с телефона и клавиатуры, отмена долгого нажатия при прокрутке, проверка прав и сохранение точного набора целей.

## Приёмка и выпуск

Предпросмотр показывает краткий итог, конкретные цели, исполнителей, причины недоступности и ожидаемые изменения. Журнал различает выбранные, допущенные, отложенные и выполненные цели, показывает причины, историю и действия команды. Перезапуск и частичный сбой сохраняют прогресс и исключают слепой повтор действия с неизвестным исходом.

На одном сценарии с 1 000 профилей проверяем скорость интерфейса и поиска, объяснимость результата по каждой цели и восстановление после сбоя без дублей. Для сравнения с конкурентами используем одинаковые пользовательские сценарии и замеряем время, число действий, успешность и восстановление. Все заявленные направления входят в один выпуск. Сначала доступ получают владелец и тестовая команда. Живые прогоны проводятся на разрешённых тестовых ресурсах.

## Текущее подключение

Экран существующей сети открывает редактор публикаций с каналами этой сети. Команда «Подготовить публикацию» из контекстного меню канала открывает тот же редактор с одним адресатом. Сервер сверяет подтверждённый список и владелец может выбрать время через существующий планировщик. Очередь повторно проверяет принадлежность каналов перед исполнением. Вход доступен через INFRAGRAM_PROJECT_PILOT_IDS, список Telegram ID через запятую. По умолчанию список пуст.

### Журнал проекта

В пилоте журнал открывается из сети проекта и использует экран операций. Публикации с project_id и существующие развёртывания с instance_id показываются в одной истории. Список, счётчики, типы и экспорт CSV/JSON ограничены проектом и владельцем. Поиск, статус и период применяются к списку. Экспорт выгружает историю проекта целиком в пределах существующего лимита выгрузки. Карточка операции показывает номер проекта и сохраняет доступ к журналу целей.

Проверка из tg-manager на отдельной тестовой БД: `INFRAGRAM_TEST_DSN=<dsn> python -m pytest -q tests/test_project_operations_postgres.py tests/test_the_operation_card_says_what_was_launched.py tests/test_the_operations_list_filters_and_acts_in_bulk.py`. Проверяются второй проект владельца, чужой владелец, запрос вне пилота, старое развёртывание, пагинация, фильтры и выгрузка. Тестовый PostgreSQL использует временные таблицы. Telegram не вызывается.

Откат: отключить пилот через INFRAGRAM_PROJECT_PILOT_IDS или откатить коммит. Миграций нет, параметры уже поставленных операций сохраняются. Нагрузочные замеры, мобильный прогон и ролевой доступ к журналу команды остаются открытыми.
