# Уникальный IP на аккаунт БЕЗ прокси (IPv6 source rotation)

## Почему не Cloudflare Workers
CF Workers выходят в интернет из **общего** пула IP Cloudflare. Сколько воркеров
ни создавай в одном аккаунте — egress-IP один на всех (эмпирически: «🩺 Проверить»
показал `уник. IP: 1` на 17 воркеров в 2 разных colo). Значит CF-релей даёт
edge-IP CDN вместо датацентра Railway (это полезно — Telegram мягче к CDN), но
**не** уникальный IP на аккаунт. Для 1:1 CF-релей не подходит.

## Настоящее решение: свой IPv6 на аккаунт
Если хосту **маршрутизирована** IPv6-подсеть (/64 = 2⁶⁴ адресов, /48 ещё больше —
часто бесплатно с VPS/dedicated), можно привязать исходящий сокет **каждого**
аккаунта к своему адресу из неё. Telegram видит уникальный IP на аккаунт — без
покупки прокси и без нескольких CF-аккаунтов.

Реализовано в `services/account_manager.py`:
- `_account_ipv6(account_id, subnet)` — детерминированно маппит account_id → свой
  адрес (один аккаунт всегда с одного IP → стабильный exit, без AUTH_KEY-рассинхрона;
  разные аккаунты → разные адреса).
- `_make_client` при заданном `IPV6_SUBNET` и отсутствии bound-прокси подключается
  напрямую (obfuscated) с `local_addr=<ipv6 аккаунта>` + `use_ipv6=True`.
  **Приоритет выше CF-релея** (реальный уникальный IP важнее общего edge-IP).
- Выключено по умолчанию (пустой `IPV6_SUBNET`) → нулевое изменение поведения.

## Требования к хосту (обязательно)
Bind к произвольному адресу подсети работает, только если:
1. Подсеть **routed** на сервер (провайдер выдал /64 или /48 и маршрутизирует его
   на ваш IP). Shared-IPv6 без делегированного блока (типичный Railway/контейнер)
   **не** подойдёт — нужен VPS/dedicated с IPv6-блоком (Hetzner/OVH/Contabo и т.п.).
2. Включён **AnyIP**, чтобы не добавлять каждый адрес вручную:
   ```bash
   ip -6 route add local 2a01:4f8:abcd::/48 dev lo
   sysctl -w net.ipv6.ip_nonlocal_bind=1
   ```
3. Есть исходящий IPv6-маршрут по умолчанию.

## Включение
```bash
# env на хосте с routed IPv6-подсетью:
IPV6_SUBNET=2a01:4f8:abcd::/48
```
После этого каждый аккаунт без своего прокси автоматически ходит со своего IPv6.
Проверить: сравнить IP, который видит внешний сервис, для 2-3 аккаунтов —
адреса должны отличаться.

## Приоритет транспорта (в `_make_client`)
1. **Bound-прокси** аккаунта (`proxy_id`) — если задан.
2. **Свой IPv6** (`IPV6_SUBNET` задан, хост поддерживает) — реальный уникальный IP.
3. **CF-релей** (`cf_relay_url`/`CF_RELAY_URL`) — общий edge-IP CDN (не 1:1).
4. Пул публичных SOCKS5 (резерв) / прямое подключение.
