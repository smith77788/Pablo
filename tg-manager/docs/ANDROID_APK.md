# Infragram на Android: PWA сейчас, APK — по кнопке

Владелец хотел работать с телефона не только через интерфейс Telegram. Сделано в
два слоя. Первый уже в проде и работает сразу; второй собирает файл `.apk`.

## Как это входит без Telegram

Мини-апп раньше пускал только через Telegram (`initData`). Отдельное приложение
так войти не может, поэтому добавлено **связывание устройства** с той же точкой
доверия — ботом:

1. в боте команда **/pair** выдаёт одноразовый код (живёт 5 минут);
2. приложение меняет код на **токен устройства** (хранится на телефоне ~30 дней);
3. приложение меняет токен устройства на обычный сессионный токен — дальше всё
   работает как в Telegram-мини-аппе.

Управление устройствами — эндпойнты `GET /api/miniapp/devices` и
`POST /api/miniapp/devices/revoke` (отзыв). Сам токен на сервере не хранится —
только его отпечаток (sha256), чтобы устройство можно было отозвать.

## Слой 1 — PWA (уже готово, ставится за 10 секунд)

1. Открыть на Android в **Chrome** адрес приложения:
   `https://ВАШ-ДОМЕН/miniapp/` (тот же `MINI_APP_URL`, со слешом на конце).
2. Меню Chrome (⋮) → **«Установить приложение»** (или «Добавить на главный
   экран»).
3. Появится иконка Infragram. Запуск — на весь экран, как приложение.
4. При первом входе появится экран **«Вход в Infragram»**: отправьте боту
   **/pair**, введите код — и приложение дальше входит само.

Это уже полностью закрывает «работать с Android вне Telegram».

## Слой 2 — настоящий файл .apk (сборка по кнопке)

Файл `.apk` (обёртка TWA вокруг той же PWA) собирается в GitHub Actions:

1. GitHub → вкладка **Actions** → workflow **build-android-apk** → **Run
   workflow**.
2. Указать **pwa_url** = `https://ВАШ-ДОМЕН/miniapp/`.
3. Дождаться сборки → открыть запуск → **Artifacts** → скачать `infragram-apk`.
4. Перекинуть `.apk` на телефон, открыть, разрешить «Установка из этого
   источника».

> Статус: workflow написан, но собирается на стороне GitHub (Android SDK нет в
> среде разработки), поэтому первый запуск — проверочный. Если упадёт — правки
> точечные (обычно версия Bubblewrap/SDK); логи запуска это покажут.

### Полный экран без адресной строки Chrome (необязательно)

По умолчанию TWA-приложение может показывать тонкую адресную строку. Чтобы её
убрать, домен должен подтвердить связь с приложением:

1. В логе сборки найдите шаг **«SHA256 отпечаток ключа»** — скопируйте отпечаток.
2. Составьте JSON:
   ```json
   [{
     "relation": ["delegate_permission/common.handle_all_urls"],
     "target": {
       "namespace": "android_app",
       "package_name": "app.ВАШ.ДОМЕН.twa",
       "sha256_cert_fingerprints": ["ВАШ:ОТПЕЧАТОК:..."]
     }
   }]
   ```
3. Положите этот JSON в переменную окружения **ANDROID_ASSETLINKS** (Railway) —
   сервер отдаст его по `/.well-known/assetlinks.json` автоматически, без правок
   кода. Переустановите/перезапустите приложение на телефоне.

### Стабильный ключ подписи (необязательно)

Сейчас workflow создаёт одноразовый ключ на каждый запуск — APK ставится, но
обновление «поверх» другого запуска потребует переустановки. Для стабильных
обновлений положите свой `keystore` в секреты репозитория и подставьте его в
шаг подписи вместо генерации `keytool`.
