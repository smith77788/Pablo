# «Хранилище» (Echo Vault) — чек-лист развёртывания

Архив бизнес-переписки через Telegram Business. Код готов (см. `services/vault_service.py`,
`bot/handlers/business_vault.py`, `schema_v163.sql`, маршруты `/api/miniapp/vault/*`).
Чтобы фича заработала на живом боте, нужны шаги, которые **нельзя сделать из кода** —
они на стороне @BotFather и владельца аккаунта.

## 1. Включить бизнес-режим у бота (@BotFather) — ОБЯЗАТЕЛЬНО

Без этого Telegram не даёт подключить бота и пишет «Этот бот пока не поддерживает
режим секретаря» ещё ДО того, как наш код вызывается.

1. Откройте **@BotFather**
2. `/mybots` → выберите нужного бота (тот же токен, что в `MANAGER_BOT_TOKEN`)
3. **Bot Settings** → **Business Mode** → **Turn on**

## 2. Право отвечать (для ответа из «Хранилища»)

Ответ собеседнику «от вашего имени» из мини-аппа работает только при праве
`can_reply`. Его выдаёт ПОЛЬЗОВАТЕЛЬ при подключении бота (переключатель доступа к
чатам/ответам в «Автоматизации чатов»). В коде это читается из
`BusinessConnection.rights.can_reply` (с фолбэком на legacy `can_reply`).

## 3. Условия на стороне пользователя

- У пользователя, который подключает бота, должен быть **Telegram Premium**
  («Telegram для бизнеса» — премиум-функция).
- Подключение: *Настройки → Telegram для бизнеса → Чат-боты* → ввести @username бота
  → разрешить доступ к чатам (и ответам, если нужно). То же описывает команда `/vault`.

## 4. Доставка апдейтов (уже в коде — проверить при смене конфигурации)

`main.py` → `_allowed_updates` должен содержать `business_connection`,
`business_message`, `edited_business_message`, `deleted_business_messages`. Без них
Telegram НЕ шлёт business-апдейты и архив молча пуст. Это же передаётся в
`set_webhook(allowed_updates=…)` и `start_polling(allowed_updates=…)`.

## 5. Зависимости/переменные

- `pycryptodome` (в `requirements.txt`) — шифрование текста at-rest (`token_vault`).
- `TOKEN_ENCRYPTION_KEY` — ключ шифрования (тот же, что для сессий/прокси).
- `MINI_APP_URL` — чтобы кнопка «Открыть Хранилище» и deep-link `#vault` работали.

## 6. Быстрая проверка (канарейка)

1. Включить Business Mode (шаг 1), задеплоить.
2. Подключить бота в свой бизнес-аккаунт (шаг 3), разрешить чаты + ответы.
3. В боте должно прийти «✅ Хранилище подключено».
4. Написать себе в любой личный чат пару сообщений; открыть «Хранилище» в мини-аппе
   (или `/vault`) — сообщения видны.
5. Удалить одно сообщение у себя → в архиве оно помечается 🗑, но текст сохраняется.
6. Ответить из «Хранилища» → собеседник получает сообщение от вашего имени.

## Что проверено автоматически, а что — только вживую

- **Проверено (live-PG + юнит):** схема, шифрование at-rest, идемпотентность,
  правки/удаления (контент сохраняется), поиск, owner-изоляция, проводка
  allowed_updates/роутер/хендлеры/маршруты/экраны. См. `tests/test_vault_e2e_postgres.py`,
  `tests/test_business_vault_wiring.py`.
- **Только вживую (нет aiogram/Telegram в CI):** фактическая доставка business-
  апдейтов и отправка через `business_connection_id`. Это шаг 6 выше.
