## Механические проверки (нет в .botmother/16,/24)

1. **Трассировка полной цепочки перед коммитом.** Маршрут реально существует (`grep router.add_*`); хендлер реально работает с БД/Telethon, а не только принимает параметры; запрос скоупится по owner_id/uid. «no dead buttons в DoD» ≠ «кнопка проверена» — была кнопка, 404-ившая с момента мерджа.
2. **Опасные sync/upsert/import_all-хелперы.** Читать тело целиком перед переиспользованием: часто внутри DELETE всего набора по ключу перед INSERT (расчёт на полную пересинхронизацию) — частичный вызов тихо стирает остальное. Тогда писать точечный `INSERT ... ON CONFLICT DO UPDATE`.
3. **Каждый принятый параметр обязан доходить до эффекта** через весь стек вызовов, не теряться по дороге (был баг: `proxy_url` принимался и никуда не передавался).
4. **Мультизначные/мультирежимные входы** (match_mode, списки через запятую) проверять по всем веткам условия, не только по первой.
5. **Воспроизводимое окружение.** `pip install -r requirements.txt` падает на нативной сборке pyaes (среда, не код; не блокирует тесты чистой логики). `tests/conftest.py` раньше стабил aiogram/asyncpg заглушками, отставшими от кода (~90/700 тестов не собирались) — почищено. Класс проблемы: формально тест есть, реально ничего не проверяет.
6. **In-memory/process-local state** помечать в docstring: «не переживает рестарт, не шарится между воркерами».
7. **Каждый найденный/исправленный баг → регресс-тест в том же коммите.** Фикс без теста не считается завершённым.

## Секреты в БД — зашифрованы (был plaintext-разрыв, ЗАКРЫТО)

`.botmother/15` и `docs/SECURITY.md` требуют шифровать сессии/прокси. Раньше `session_str` (`tg_accounts`/`booster_sessions`, = полный доступ к аккаунту) и `proxy_url` (`user_proxies`) писались открытым текстом — самый серьёзный разрыв декларации и реальности. Сейчас шифруются через `services/token_vault.py` (AES-256-GCM) на всех точках записи; расшифровка централизована (сессии → `account_manager._make_client`; прокси → все листья потребления). Дедуп/UNIQUE/ON CONFLICT — по детерминированным `session_fp`/`proxy_fp = sha256(plaintext)` (шифротекст AES-GCM недетерминирован). Legacy plaintext читается прозрачно (`decrypt_token` passthrough без префикса `ENC:`). Форс-миграция старых строк — `deploy/scripts/encrypt_legacy_secrets.py` (dry-run, ещё НЕ запущен). Регресс: `tests/test_session_encryption.py`, `test_proxy_encryption.py`, `test_booster_session_encryption.py`. Вне периметра: `nodes-service/` (TS-микросервис со своей таблицей) — при выходе в прод нужен свой проход.
