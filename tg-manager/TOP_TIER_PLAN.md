# Infragram Top-Tier Improvement Plan

## Приоритеты

1. **Надёжность** — операции не падают, аккаунты не ломаются
2. **UX** — каждый экран работает без тупиков
3. **Интеллект** — система учится и предсказывает
4. **Производительность** — быстрее конкурентов
5. **Безопасность** — защита данных и аккаунтов

---

## Модуль 1: Operation Engine (op_worker.py) — ЯДРО

### Что есть
- 53 op_type, 50 exec функций, 182 safe-хелпера
- Базовый retry, progress, cancel

### Что нужно для Tier-1

**A. Adaptive Pacing (интеллектуальные задержки)**
- [ ] Система учитывает время суток, день недели, поведение целевого канала
- [ ] Автоматическое замедление при приближении к лимитам Telegram
- [ ] Machine learning на истории: какие паттерны вызывают бан

**B. Circuit Breaker (аварийный выключатель)**
- [ ] Если 3+ аккаунта подряд получают FloodWait — автопауза на 30мин
- [ ] Если proxy падает — автоматическое переключение на backup proxy
- [ ] Если операция падает 3 раза подряд — уведомление админу + автопауза

**C. Smart Retry (умный повтор)**
- [ ] При FloodWait — ждать ровно столько, сколько Telegram просит + jitter
- [ ] При PeerFlood — чередовать аккаунты, не повторять на том же
- [ ] При CHANNEL_PRIVATE — помечать канал как приватный и пропускать
- [ ] При AUTH_KEY dead — деактивировать аккаунт и уведомить

**D. Progress Reporting (отчёт о прогрессе)**
- [ ] Live-обновления в Telegram каждые 30сек для длинных операций
- [ ] ETA на основе средней скорости
- [ ] Сводка в конце: что получилось, что нет, почему

## Модуль 2: Account Manager (account_manager.py) — АККАУНТЫ

### Что есть
- 72 async функции, 81 proxy-паттерна, 498 session-упоминаний

### Что нужно для Tier-1

**A. Session Health Monitor (мониторинг сессий)**
- [ ] Автоматическая проверка сессий каждые 6 часов
- [ ] При ошибке "AUTH_KEY dead" — немедленная деактивация
- [ ] При ошибке "FLOOD_WAIT" — увеличение cooldown пропорционально
- [ ] При "USER_DEACTIVATED" — пометка как "забанен Telegram"

**B. Proxy Intelligence (интеллект прокси)**
- [ ] Автотест прокси перед использованием: ping + test connection
- [ ] Автопереключение на backup при деградации
- [ ] Статистика по прокси: uptime, latency, success rate
- [ ] Рекомендации: какой прокси лучше для какого региона

**C. Account Rotation (ротация аккаунтов)**
- [ ] Автоматический выбор наименее использованного аккаунта
- [ ] Балансировка нагрузки между аккаунтами
- [ ] Учёт trust_score при выборе
- [ ] Исключение аккаунтов в cooldown

**D. Session Import Hardening (надёжный импорт)**
- [ ] Валидация сессий перед импортом: проверка auth key
- [ ] Автоопределение формата: StringSession / Pyrogram / tdata
- [ ] Откат при ошибке: не ломать существующие сессии
- [ ] Пакетный импорт с прогресс-баром

- [ ] Автовыбор вектора на основе платформы
- [ ] Кастомные пресеты с сохранением
- [ ] A/B тестирование пресетов

**C. Reporting (отчётность)**
- [ ] Детальный отчёт по каждому удару: что сделано, результат
- [ ] Статистика: сколько жалоб, сколько удалений, сколько банов
- [ ] История ударов по каналам
- [ ] Экспорт отчётов в PDF/Telegram

## Метрики успеха

### Stability
- 99.9% операций завершаются успешно
- 0 крашей op_worker за сутки
- <1% ошибок proxy

### UX
- Время отклика <500ms
- 0 тупиков в навигации
- 100% экранов с Cancel/Back

### Intelligence
- Автоматический выбор оптимального прокси
- Предсказание банов с точностью >80%
- Auto-tuning параметров

### Performance
- Массовые операции: >100 аккаунтов/час
- Mini App загрузка: <2сек
- API response: <200ms
