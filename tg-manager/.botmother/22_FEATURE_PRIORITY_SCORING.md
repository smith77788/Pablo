# Feature Priority Scoring

> Advisory only — this helps *order* work; it is never a basis to refuse or block
> work the owner asked for (including expanding mass-action modules or adding new
> ones). The only hard constraints are the protective gates in `../CLAUDE.md`.

Prefer not to spend effort on impressive-sounding features just because they appear
in the vision — but this is a hint for prioritization, not a prohibition.

Before choosing work, score each candidate:

- user impact
- reusability
- architectural leverage
- mass-operation leverage
- safety improvement
- UX improvement
- implementation complexity
- maintenance cost
- risk of breaking existing flows

Prioritize:

1. Broken existing flows
2. Safety and reliability
3. Operation Engine foundations
4. Targeting and reports
5. Telegram-native UX clarity
6. Import and discovery
7. Templates / DNA / drift
8. Visibility and intelligence
9. Billing and governance
10. Advanced automation

Avoid:

- isolated niche features
- cosmetic complexity
- dead menus
- fake placeholders
- features without preview/retry/reporting
- advanced systems on unstable foundations
